# Authplane Rust SDK — LLM Guide

Short guide. For complete context and detailed examples, read `llm-full.txt`.

## What this repo provides

A Cargo workspace containing the framework-agnostic Authplane SDK and an
MCP adapter for protecting MCP servers and OAuth 2.1 resource servers
with tokens issued by an Authplane authorization server.

Crates (published independently on crates.io):

- `core/` — crate `authplane-sdk` — full OAuth 2.1 client, token
  verification, DPoP, SSRF-hardened transport, circuit breaker, and
  caching.
- `mcp/` — crate `authplane-mcp` — thin adapter for the
  [rmcp](https://crates.io/crates/rmcp) MCP framework with URL-elicitation
  helpers.
- `fastmcp/` — crate `authplane-fastmcp` — thin adapter for
  [fastmcp-rust](https://crates.io/crates/fastmcp-rust) with URL-elicitation
  helpers; supports both stdio and HTTP transports.

## Architecture rules

- Typed error definitions and OAuth mapping live in `core/` (crate
  `authplane-sdk`).
- Adapters (`mcp/`, `fastmcp/`) must stay thin: detect consent /
  interaction-required SDK errors and raise framework-specific errors
  (e.g. MCP URL-elicitation error `-32042` when `consent_url` is present).
- Do not duplicate error types or OAuth mapping in the adapters.
- Preserve typed metadata for consent flows (`service_id`, `cause_detail`,
  `consent_url`).
- Adapter wrappers stay minimal and stateless.

## Minimal usage example

```rust
use authplane_sdk::{parse_token_exchange_error, AuthplaneError};

let err = parse_token_exchange_error(Some(400), body);
if let AuthplaneError::ConsentRequired(consent) = err {
    // prompt the user, or (in an adapter) raise a URL-elicitation error
}
```
